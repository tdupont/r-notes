14  Building Interactive Apps with Shiny

Shiny lets you build interactive web applications directly from R. No HTML, CSS, or JavaScript knowledge is required to get started — though you can add them for advanced customisation.

14.1 Anatomy of a Shiny app

Every Shiny app has three components:

  1. UI (ui) — defines the layout and appearance (frontend)
  2. Server (server) — contains the computational logic (backend)
  3. shinyApp() — combines them into a runnable app
library(shiny)

ui <- fluidPage()  # minimal empty UI

server <- function(input, output, session) {}  # empty server

shinyApp(ui = ui, server = server)

Run the app with runApp("path/to/app/") or by clicking Run App in RStudio.

14.2 The workflow: input → server → output

User interacts with input widget
    ↓
input$id changes value
    ↓
server recomputes output$id
    ↓
Output renders in the UI
  • Inputs are always defined in the UI and accessed in the server as input$inputId.
  • Outputs are rendered in the server and displayed in the UI via *Output() functions.

14.3.2 Standard layout with sidebar

ui <- fluidPage(
  titlePanel("My Clinical Dashboard"),
  sidebarLayout(
    sidebarPanel(
      textInput("name", "Patient name:"),
      sliderInput("age", "Age:", min = 0, max = 120, value = 50),
      selectInput("group", "Group:", choices = c("Control", "Treated"))
    ),
    mainPanel(
      plotOutput("survival_plot"),
      tableOutput("summary_table")
    )
  )
)

14.4 Server logic

server <- function(input, output, session) {

  # Render a plot that depends on the input
  output$survival_plot <- renderPlot({
    df_filtered <- patients |>
      filter(group == input$group, age <= input$age)

    ggplot(df_filtered, aes(x = time, y = survival)) +
      geom_line() +
      labs(title = paste("Group:", input$group))
  })

  # Render a summary table
  output$summary_table <- renderTable({
    patients |>
      filter(group == input$group) |>
      summarise(n = n(), median_los = median(los))
  })

}

14.5 Reactive programming

Shiny uses reactive expressions to avoid unnecessary recomputation. A reactive expression caches its value and only re-runs when its inputs change.

server <- function(input, output, session) {

  # Reactive expression: filtered data (recomputes only when input$group changes)
  filtered_data <- reactive({
    patients |> filter(group == input$group)
  })

  # Multiple outputs can share the same reactive expression
  output$plot  <- renderPlot({ ggplot(filtered_data(), ...) })
  output$table <- renderTable({ filtered_data() })

}

14.5.1 observeEvent() — respond to button clicks

observeEvent(input$run_analysis, {
  # This block runs only when the button is clicked
  output$result <- renderText(paste("Analysis run with n =", input$n))
})

14.7 Complete working example

library(shiny)
library(babynames)
library(ggplot2)

ui <- fluidPage(
  titlePanel("Baby Name Explorer"),
  sidebarLayout(
    sidebarPanel(
      textInput("name", "Enter a name:", value = "Emma")
    ),
    mainPanel(
      plotOutput("trend", height = "400px")
    )
  )
)

server <- function(input, output, session) {
  output$trend <- renderPlot({
    babynames |>
      filter(name == input$name) |>
      ggplot(aes(x = year, y = prop, color = sex)) +
      geom_line(linewidth = 1) +
      labs(
        title = paste("Popularity of", input$name, "over time"),
        x = "Year", y = "Proportion of births"
      ) +
      theme_minimal()
  })
}

shinyApp(ui = ui, server = server)
